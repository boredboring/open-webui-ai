# 课程 AI 助教 · 接口约定

> 版本：v0.1
> 维护人：项目统筹 / 助教与集成负责人
> 适用对象：知识库负责人、扩展工具负责人、测试负责人、部署与文档负责人
> 状态：草案，待团队确认后冻结。确认前课程名称等灰色字段可整体替换，接口字段不变。

## 1. 目标

本文件用于统一「课程 AI 助教」项目各模块之间的协作边界，让知识库、助教模型、扩展工具、测试四类工作可以并行开发，最后能无歧义地联调。

核心原则：

- 每方只依赖本文件中约定的字段和格式，不依赖对方的实现细节。
- 所有「外部可复用」的产物都要有稳定 ID、版本号和状态。
- 引用、错误处理、工具返回结构必须统一，便于自动化测试判分。

## 4. 命名与目录约定

### 4.1 目录结构

建议统一使用英文目录名，便于脚本和 Git 处理；中文说明放在文件名或文档内。

```text
docs/
├── interface-agreement.md      # 接口约定（本文件）
├── deployment/                 # 部署说明与证据
├── prompts/                    # 系统提示词
├── knowledge/                  # 知识库资料与清单
├── tools/                      # 扩展工具设计文档
├── testing/                    # 测试用例与执行记录
├── evidence/                   # 截图、日志、交互记录
└── report/                     # 项目总结报告
```

> 目录与文档文件统一使用英文命名，便于脚本、Git 和跨平台引用。

### 4.2 命名规则

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 知识库 | `kb_{课程代号}_{序号}` | `kb_ds_001` |
| 文档 | `{课程代号}_{章节}_{类型}_{序号}.{扩展名}` | `ds_ch03_lecture_01.md` |
| 助教模型 | `{课程中文名} AI 助教` | `数据结构 AI 助教` |
| 系统提示词 | `{course_code}-assistant-system-prompt.md` | `ds-assistant-system-prompt.md` |
| 扩展工具 | `{课程代号}_{功能}` | `ds_quiz_generator` |
| 测试用例表 | `test_cases_{课程代号}.csv` | `test_cases_ds.csv` |
| Git 分支 | `codex/{模块}` | `codex/knowledge` |

## 5. 知识库接口

### 5.1 知识库信息（知识库负责人 → 助教 / 测试）

| 字段 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| kb_id | 是 | kb_ds_001 | 稳定 ID |
| kb_name | 是 | 数据结构课程知识库 | 展示名称 |
| description | 是 | 覆盖数据结构第 1-7 章 | 说明范围 |
| owner | 是 | 成员姓名 | 负责人 |
| status | 是 | ready | `draft / indexing / ready / failed` |
| version | 是 | v1.0 | 每次重建递增 |

### 5.2 资料清单（必填）

每个资料文件在 `docs/knowledge/knowledge-inventory.md` 中登记一行，要求不少于 8 个文件或不少于 30 页，至少包含 3 类资料，并按章节分类。

| 序号 | doc_id | 文件名 | 章节 | 资料类型 | 来源 | 页数 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | ds_ch01_lecture_01 | ds_ch01_lecture_01.md | 第 1 章 | 课件 | 教师提供 | 4 | ready |
| 2 | ds_ch02_lab_01 | ds_ch02_lab_01.md | 第 2 章 | 实验指导 | 实验指导书 | 3 | ready |
| 3 | ds_ch03_code_01 | ds_ch03_code_01.py | 第 3 章 | 示例代码 | 小组编写 | 1 | ready |

资料类型枚举：

- `lecture`：课件 / 讲义
- `lab`：实验指导书
- `textbook`：教材节选
- `reference`：教师提供的参考资料
- `note`：小组自编知识点文档
- `code`：示例代码与常见错误说明

### 5.3 检索参数（默认值，可实测调整）

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| top_k | 5 | 检索片段数量 |
| chunk_size | 500 | 文档切分大小 |
| chunk_overlap | 50 | 相邻块重叠 |
| hybrid_search | true | 向量 + 关键词混合检索 |
| rerank | 可选 | 可用则开启 |
| embedding_model | 环境可用模型 | 需在文档中写明实际使用值 |

调整检索参数后，知识库负责人需同步更新本表并通知测试负责人重新跑用例。

### 5.4 验收标准

- 知识库能被助教模型检索。
- 有资料的题目能给出正确引用。
- 无资料的题目能触发「资料中未找到」而不是编造。

## 6. 助教模型接口

### 6.1 模型信息（助教负责人 → 工具 / 测试）

| 字段 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| model_name | 是 | 数据结构 AI 助教 | 展示名称 |
| model_id | 是 | 创建后填写 | 联调时使用 |
| base_model | 是 | DeepSeek | 基础模型 |
| provider | 是 | OpenAI 兼容 | 连接类型 |
| system_prompt_path | 是 | docs/prompts/ds-assistant-system-prompt.md | 提示词文件 |
| knowledge_ids | 是 | kb_ds_001 | 挂接知识库 |
| tool_ids | 是 | ds_quiz_generator | 挂接工具 |
| version | 是 | v1.0 | 每次提示词变更递增 |
| status | 是 | ready | `draft / ready / disabled` |

### 6.2 系统提示词必须覆盖

1. AI 助教身份。
2. 服务的课程范围。
3. 回答格式。
4. 引用要求。
5. 学术诚信要求。
6. 无法确认答案时的处理方式。
7. 作业不代写原则（先给提示、思路、分步指导）。

### 6.3 标准回答格式

助教优先使用以下结构回答课程问题：

```text
【直接结论】
……

【解释】
……

【示例 / 代码 / 解题思路】（如适用）
……

【来源】
- [来源：《文件名》｜第X章｜“原文片段”]

【不确定声明】（如适用）
资料中未找到相关信息，我不确定……
```

### 6.4 引用格式约定

- 标准引用：`[来源：《文件名》｜第X章｜“原文片段”]`
- 无资料时必须使用固定句式：`资料中未找到相关信息，我不确定……`
- 超出课程范围时：明确说明“这超出本课程范围”，再判断是否拒绝回答或给简短方向。

## 7. 扩展工具接口

### 7.1 工具信息（工具负责人 → 助教 / 测试）

每个工具至少提供以下元数据，登记在 `docs/tools/tool-catalog.md`。

| 字段 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| tool_id | 是 | ds_quiz_generator | 稳定 ID |
| tool_name | 是 | 章节练习题生成 | 展示名称 |
| tool_type | 是 | Workspace Tool | `Workspace Tool / Skill / 外部 API` |
| description | 是 | 根据章节生成练习题 | 给模型判断何时调用 |
| input_schema | 是 | 见 7.2 | JSON Schema |
| output_schema | 是 | 见 7.2 | JSON Schema |
| examples | 是 | 见 7.3 | 至少 2 条自然语言示例 |
| version | 是 | v1.0 | 版本 |
| owner | 是 | 成员姓名 | 负责人 |
| status | 是 | ready | `draft / ready / disabled` |

要求：

- 必须是真实工具或结构化数据处理，不能用提示词模拟。
- 工具输入输出尽量使用 JSON，便于测试判分。
- 工具必须能在 Open WebUI 对话中被调用。

### 7.2 输入输出结构示例（模板，实际以工具负责人为准）

以「章节练习题生成」为例：

```json
{
  "input": {
    "chapter": "第3章",
    "question_count": 5,
    "difficulty": "medium",
    "question_type": "choice"
  },
  "output": {
    "ok": true,
    "data": {
      "questions": [
        {
          "id": "q1",
          "type": "choice",
          "stem": "……",
          "options": ["A. …", "B. …", "C. …", "D. …"],
          "answer": "B",
          "explanation": "……"
        }
      ]
    }
  }
}
```

错误返回统一结构：

```json
{
  "ok": false,
  "error": {
    "code": "INVALID_CHAPTER",
    "message": "未找到该章节"
  }
}
```

### 7.3 工具调用示例（测试用）

工具负责人至少提供 2 条自然语言触发示例，测试负责人按同样句式验证：

- “帮我生成第 3 章的 5 道选择题，难度中等。”
- “从第 2 章随机抽 3 道题。”

### 7.4 本组扩展功能建议

可在以下功能中选择至少一个实现：

- 章节练习题生成
- 随机抽题
- 客观题自动判分
- 学习计划生成
- 课程章节查询
- 编程题测试用例生成
- 知识点先修关系查询

## 8. 测试与验收接口

### 8.1 测试用例表字段

测试负责人将用例登记在 `docs/testing/test_cases_ds.csv`，字段如下：

| 字段 | 说明 |
| --- | --- |
| case_id | 用例编号，如 T01 |
| category | 用例类别 |
| input | 测试输入 |
| expected | 预期行为 |
| actual_output | AI 实际输出 |
| citation_correct | 是否引用正确资料（`是/否/不适用`） |
| answer_correct | 回答是否正确（`是/否/部分`） |
| problem | 存在的问题 |
| improvement | 改进方式 |
| phase | `before / after`（优化前或优化后） |
| result | `通过 / 失败` |

### 8.2 用例数量要求

| 类别 | 最少数量 |
| --- | --- |
| 课程知识问答 | 5 |
| 综合分析问题 | 3 |
| 知识库中没有答案的问题 | 2 |
| 练习题生成或批改任务 | 2 |
| 自定义工具调用任务 | 2 |
| 错误输入或异常情况 | 1 |

## 9. Git 与提交约定

### 9.1 分支

| 分支 | 用途 |
| --- | --- |
| main | 稳定主线 |
| codex/knowledge | 知识库相关内容 |
| codex/assistant | 助教模型与提示词 |
| codex/tool | 扩展工具 |
| codex/deployment | 部署说明与证据 |
| codex/testing | 测试用例与记录 |
| codex/report | 总结报告 |

### 9.2 提交信息

使用 `type(scope): subject` 格式：

```text
feat(assistant): 新增数据结构 AI 助教系统提示词
docs(deployment): 补充 DeepSeek 接入与排错说明
fix(tool): 修正章节练习题生成工具的判分逻辑
test(testing): 增加优化前 15 个测试用例
```

### 9.3 数据与产物约定

- `backend/data/webui.db`、Chroma 向量库等本地运行数据不入库，避免污染仓库。
- 入库交付物：文档、提示词、工具代码、测试记录、证据截图、报告。
- 每人完成一个功能后提 PR，由项目统筹统一合并到 `main`。

## 10. 联调检查清单

端到端联调前逐项确认：

1. 知识库已索引完成，`kb_id` 已填写。
2. 资料清单与知识库实际内容一致。
3. 助教模型已挂接正确知识库和工具。
4. 系统提示词覆盖 6.2 的全部 7 项要求。
5. 工具 `tool_id`、`input_schema`、`output_schema`、`examples` 已提供。
6. 至少一条知识问答、一条工具调用、一条超出范围用例能跑通。
7. 引用格式和「资料中未找到」句式符合本约定。
8. 测试用例表已更新并包含 `before / after` 对比。
