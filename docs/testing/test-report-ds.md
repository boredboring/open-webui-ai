## 1. 结论摘要

| 指标 | 优化前（before） | 优化后（after） |
| --- | --- | --- |
| 用例总数 | 16 | 16（同一批评测问题） |
| 通过 | 4（25%） | 7（44%） |
| 部分通过 | 2（13%） | 9（56%） |
| 失败 | 10（63%） | 0（0%） |
| 引用正确（是/部分 占比） | 0 / 0 | 4 / 8 |
| 回答正确（是/部分 占比） | 14 / 2 | 15 / 1 |

核心结论：

1. **优化后 0 失败**：挂接知识库 + 系统提示词 v0.3 + 检索参数调优后，所有用例至少“部分通过”，知识库无答案类问题由“编造/误答”转为“资料中未找到 + 明确免责 + 引导”，是本次优化最明显的收益。
2. **检索召回仍是短板**：知识问答/综合分析（T01、T03–T07）经常召回到“相邻但不相关”的片段，或明确说明“资料未提供对应内容”，说明当前 `all-MiniLM-L6-v2`（英文优化）对中文课件召回不足，`7.2.2/8.3.2/2.3.6` 等目标文件未被命中。
3. **工具链路（抽题/判分）稳定**：T11–T14、T16 在前后两轮均真实调用 `ds_random_quiz` / `ds_grade_quiz`，判分与错误处理正确；剩余问题主要是**题库容量**（每章仅 4 题、选择题仅 2 道，无法满足“5 道”“4 道”请求）。
4. **引用样式未统一**：系统提示词约定 `[来源：《文件名》｜第X章｜“原文片段”]`，但 RAG 注入模板产生 `[编号]` 引用，模型输出以 `[1][2]` 为主，需在模板层统一。

## 6. 主要问题与改进清单

### P0（建议优先处理）
1. **中文检索召回不足（影响 T01、T03–T07 引用质量）**：目标课件文件（如 `7.2.2_折半查找.md`、`2.3.6_顺序表和链表的比较.md`、`8.3.2_快速排序.md`）常未被召回，模型只能“诚实说明未命中 + 用通用知识回答”。
   - 改进：切换多语言/中文嵌入模型（bge-m3、m3e、text2vec 等）；开启 rerank；验证 chunk=500/overlap=50 与 hybrid 权重（当前 bm25 权重 0.5）；按目标文件做 2–3 个回归问题验收。
2. **引用样式不一致**：RAG 模板产出 `[编号]`，与 v0.3 约定 `[来源：《文件名》｜第X章｜“原文片段”]` 不一致。
   - 改进：在检索模板（rag.template）或系统提示词中统一引用输出格式，并对“编号→文件”映射做人工复核。

### P1
3. **“无答案”处理不一致（T09 vs T10）**：T09 已做到“未找到+不展开”；T10 在免责后仍展开完整算法，且把“拓展内容”归因到 [1] 略牵强。
   - 改进：v0.3 第八节补充示例——“资料未找到时只给 1–2 句说明并引导回课程范围，不展开超范围讲解”。
4. **题库容量不足**：每章 4 题（选择仅 2 道），T11/T14 的“5 道”“4 道”无法满足。
   - 改进：扩充题库（建议每章 ≥8 题、题型均衡）；或工具返回不足时模型明确“题库仅有 X 道”并询问是否放宽条件（after 已能较好说明）。

### P2
5. **无提示词时的工具误用（T09/T10 before）**：优化前模型会把“跳表/笛卡尔树章节问题”误解为“抽题请求”而反复调用抽题工具。
   - 改进：已由 v0.3（角色+范围+先判断）解决；后续回归保留 T09/T10 两个用例即可。
6. **evidence 检索来源未落库**：本轮 `chat_message.sources` 未记录检索片段（Open WebUI API 路径），引用核对依赖输出中 [编号] 与内容。
   - 改进：后续可在 UI 侧录制或扩展 API 参数收集 `sources`，便于自动化判引用。
